Dla developerów

Chrome DevTools Snippet

W DevTools otwórz Sources → Snippets, utwórz snippet, wklej kod i uruchamiaj go skrótem Ctrl+Enter. Snippet zawiera pełny runtime i nie pobiera skryptów z TDW.

Scenariusz

Jak używać

  1. Uruchom launcher na badanej stronie. W prawym dolnym rogu pojawi się przycisk TDW bez przejmowania strony.
  2. Otwórz menu i wybierz UX Inspector. Dopiero teraz włączy się tryb zaznaczania; Escape wraca do launchera.
  3. Najedź i kliknij element. Klik jest przejmowany przez Inspector i nie uruchamia akcji aplikacji.
  4. Dokończ pytanie w TDW. Dedykowany ekran UX Inspectora odbierze capture. Dopisz pytanie, potwierdź system, branch, view, model i reasoning effort, a następnie uruchom job.
✓

Minimalny dostęp

Launcher nie ma uprawnień w tle, nie przechowuje ustawień i nie otrzymuje tokenów TDW. Wartości formularza są pobierane tylko po jawnym wybraniu profilu Formularz; hasła, pola ukryte, pliki i dane wyglądające jak sekrety są zawsze wykluczane. Narzędzie nie czyta cookies, storage, ruchu sieciowego ani screenshotów. Capture nadal traktuj jako niezaufane dane strony i sprawdź podsumowanie targetu przed uruchomieniem analizy.

Zakładka jest nietypowo duża. Odśwież installer przed ponownym dodaniem zakładki. W razie problemów użyj pełnego DevTools Snippetu.
Szczegóły techniczne i ograniczenia
  • Obsługiwane są zwykłe strony HTTP(S) w top-level dokumencie.
  • CSP może blokować pobranie runtime, a Chrome może poprosić stronę o zgodę na dostęp do lokalnego TDW. Wtedy użyj pełnego Snippetu.
  • Cross-origin iframe i chronione strony Chrome nie są obsługiwane.
  • Popup blocker lub Cross-Origin-Opener-Policy może przerwać transfer. Operacja kończy się wtedy błędem i nie udostępnia ręcznego transferu.
  • Bookmarklet wykonuje wyłącznie GET statycznych plików z przypiętego originu TDW i nie przekazuje referrera. Kod selektora działa w main world badanej strony i dlatego nie zawiera żadnych sekretów.
